# 后续开发交接

产品目标：医学本科生按周平衡，首页每天最多 1–3 个可执行行动；保护睡眠与基本生活。

已实现今日推荐、课程与课堂 A/B/C 模式、课后关闭与问题池、单科周复习、作业分级、生活与发展方向、周复盘。首次示例是临时体验；开始个人一周后，记录保存在服务端，并按登录用户隔离。

关键位置：

- app/balance-app.tsx：页面、表单与操作。
- app/globals.css：桌面和手机布局。
- lib/balance.ts：数据校验与推荐规则。
- lib/ai-provider.ts：**模型接入点**（全仓库唯一 fetch 外部模型地址的地方，默认本地模板）。
- lib/planner.ts：旧的规划占位实现，规则规划已移到 lib/study-plan.ts（推荐规则仍在 lib/balance.ts 的 recommend）。
- app/api/v1/plan/route.ts：已有可调用规划接口。
- app/api/state/route.ts：保存记录，带版本冲突保护。
- db/schema.ts 与 drizzle/：数据库结构和迁移。
- docs/API.md：请求、响应与认证约定。

继续开发时优先拆分页面组件、补实际课程模板和规则案例，再接模型。不得让模型建议绕过时间容量、生活底线、最多三项及用户确认写入的规则。

当前 API 依赖站点登录会话，没有独立服务端 Bearer token；外部服务接入时应设计受限、可撤销的认证，密钥只能放服务器配置。不要把真实学习记录、会话、密钥或本机数据库提交到公开仓库。

已知首版边界：课表占用通过手动填写扣除后的可用时间反映；尚无课表导入、通知推送、跨时区设置或模型服务。日期以 Asia/Shanghai 计算。数据目前按用户保存为一个有版本号的文档，适合个人 MVP。

## 资料与题库更新

已增加 app/library-panel.tsx、lib/library.ts 和 /api/v1/materials。课程资料支持原文件上传或 HTTPS 链接，私有 R2 保存文件；单选题可录入、JSON 导入、练习和筛选最近错题。答错自动生成问题池记录，答对不自动关闭知识卡点。

后续优先补：资料归档与改名、分页检索、PPT/PDF 的异步解析状态、页码定位、简答题的自评记录、复习时长与练题记录关联。AI 出题必须展示来源和待确认状态。不要把上传成功等同于解析成功；不要默认从任意链接抓取内容。

空白页防护：首次读取有 15 秒超时、失败可重试；React 客户端异常显示恢复入口。仍需保留线上日志排查网络或部署加载问题。

## 学习教练（计划 / 预习复习 / 重点提炼 / 重点讲解）

系统已从「记录工具」升级为「学习教练」：按时间可用性、紧急度、重要度、前置关系、预计耗时和恢复资源，自动生成今天（最多 3 个关键行动）和本周（课前 10 分钟 / 课后 30 分钟 / 周末 120 分钟深度复习，时长随负荷、掌握度、距考试天数和当天余量动态调整）的计划；支持正常周 / 忙周 / 考试周，改过可用时间就能重新规划。

关键位置：

- lib/study-plan.ts：今天与本周的计划生成（前置关系、降级提示、临时覆盖）。
- lib/study-rhythm.ts：动态时长（基准 × 系数，每个系数配一句人话解释，最后夹到上下界）。
- lib/highlights.ts：重点提炼规则（本周重点 / 高频考点 / 未掌握点，每条都能指回原句）。
- lib/coach-context.ts：把勾选的资料、粘贴的文本、卡点和错题装配成上下文（存储通过注入的 TaskStore 访问，可直接测）。
- lib/explain.ts：重点讲解的四段式（框架 → 机制与因果 → 举例 → 问题检查）与本地模板。
- lib/ai-provider.ts：模型接入点，默认本地模板，不发任何请求。
- app/coach-panel.tsx：教练面板；app/library-panel.tsx 的资料卡片上也有「提炼重点讲解」入口。
- app/api/v1/schedule/{plan,availability}/route.ts、app/api/v1/knowledge/highlights/route.ts、app/api/v1/explain/route.ts：四个新接口，输入校验在 lib/coach-api.ts。
- docs/COACH_AI.md：**接入真实模型前先读这一份**（环境变量、请求形状、用户需要提供的数据、仍需外部的部分）。
- docs/API.md：四个接口的字段、错误码与「不落库」语义。

边界仍然有效：模型建议不得绕过时间容量、最多 3 个行动、睡眠底线、前置关系和用户确认后才写入；本地模板不编造医学结论（只给脚手架和用户资料里的原句）；重点提炼和讲解的结果不落库，用户确认后才写成知识点。这一版没有新增表和迁移，`drizzle/0000`–`0002` 不要改。
